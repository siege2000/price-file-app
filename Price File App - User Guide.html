Price File App

User Guide — for pharmacy staff

Overview

The Price File App is a desktop tool for importing price files received from suppliers and loading them into the RxOne database. It has two main areas:

  • Price File — import regular price files (cost, retail, barcodes) from suppliers.
  • Specials File — import promotional or catalogue specials sent by brands.

Both modules read from CSV or Excel files, let you review and clean the data, and then write it directly into the database.

Starting the App

Double-click PriceFileApp.exe in the application folder. The window will open and connect to the database automatically. You will see two tabs at the top — Price File and Specials File.

💡 The first launch may take 3–5 seconds while the app loads. This is normal.

Price File Module

Import regular supplier price files — costs, retail prices, barcodes, descriptions — into the RxOne database.

Typical Workflow

Each time you receive a new price file from a supplier, follow these steps in order:

Select SupplierChoose the supplier from the dropdown. The app quietly fetches their current data in the background.
Open FileBrowse to the CSV or Excel file the supplier sent.
Choose a Template & Map ColumnsSelect the appropriate template (or leave on General) and check column mappings.
Set TradeName OptionsConfigure how the product description will be built from the file's columns.
Build OutputClick Build Output to process the file and create the cleaned data set.
Preview ChangesClick Preview Changes to compare the new data against what is already in the database.
Fix DescriptionsEdit any descriptions that are too long (over 40 characters).
Save SettingsClick Save Settings so your column choices are remembered for next time.
Write to DatabaseClick Execute Upsert (or Replace All) to update the database.

Step 1 — Select a Supplier

In the Supplier panel on the right side of the screen, choose the supplier from the dropdown list.

As soon as you select a supplier, the app starts fetching their existing database records in the background. By the time you have loaded a file and built the output, the data will be ready and Preview Changes will respond almost instantly.

ℹ️ If a supplier has more than one sheet layout saved (for example when they send different product categories on separate sheets), a Sheet layout dropdown will appear. Select the appropriate layout before opening the file.

Step 2 — Open a File

Click the Open File button and browse to the price file the supplier sent. The app accepts .csv and .xlsx / .xls files.

If the Excel workbook has more than one sheet, a popup will appear asking you to choose which sheet to load. Select the correct sheet and click Load Sheet.

Once loaded, a preview of the raw file data will appear in the Source Data Preview table so you can check it looks right before mapping.

Step 3 — Map Columns

The Column Mapping section tells the app which column in the supplier's file corresponds to each field in the database. Use the dropdowns to set:

FieldWhat it is
PLUProduct Look-Up number (RxOne's product code)
PharmacodeIndustry pharmacode
Barcode / EANBarcode on the product
Supplier CodeThe supplier's own product code
RetailRecommended retail price
CostYour cost / buy price
OuterOuter / case quantity

Templates make this easier. Known suppliers have pre-defined templates that fill the column mappings automatically. The General template attempts to guess the columns from their names.

💡 If you use the same supplier regularly, save your column settings after the first import and they will be remembered every time.

Step 4 — TradeName / Description Settings

The TradeName is the product description that will be saved to the database. This section controls how it is built from the columns in the supplier's file.

SettingWhat it does
Description columnsSelect one or more columns whose values will be combined to form the description.
SeparatorText placed between each column when combining (e.g. a space or a dash).
PrefixOptional text added to the start of every description (e.g. a house-brand label).
Title CaseConverts the description to Title Case (first letter of each word capitalised).
Normalise unitsTidies up measurements — for example converts "75 g" to "75g".
⚠️ Descriptions must be 40 characters or fewer. Rows that are too long are highlighted in red and must be shortened before you can write to the database.

Step 5 — Build Output

Click Build Output. The app processes the file, applies your TradeName settings, removes rows with no identifying key (no barcode, pharmacode, or supplier code), and de-duplicates by PLU (keeping the last occurrence).

A row count will appear in the status bar. You can now see the cleaned result in the output table, including a CharCount column showing the length of each description.

Step 6 — Preview Changes

Click Preview Changes to compare your output against the existing database records for this supplier. Each row is colour-coded:

Green — NEW: product does not yet exist in the database
Yellow — UPDATE: product exists and something has changed
Grey — UNCHANGED: no differences found

The preview columns show the old and new values for description, cost, and retail so you can see exactly what will change.

Removing rows from the preview

If you do not want to update certain rows, click to select them and press Delete. They will be removed from the preview and will not be written to the database.

Step 7 — Fix Long Descriptions

Any description over 40 characters is flagged with ⚠ and highlighted in red in the Chars column. You have two options:

  • Edit manually: Double-click the New_Description cell and type the corrected text. The character count updates as you type.
  • Bulk Truncate: Click the Bulk Truncate button to automatically cut all over-length descriptions to 40 characters.
💡 Use Shortening Rules (see below) to set up automatic find-and-replace substitutions that run every time you build output for that supplier — much faster than fixing manually each time.

Step 8 — Save Settings

Click Save Settings to store the current column mappings, TradeName configuration, skip-rows setting, and template for this supplier. Next time you select this supplier and open a file, everything will be pre-filled for you.

If you work with different sheet layouts for the same supplier (e.g. different product categories on separate sheets), you can save up to six separate layouts per supplier using the Sheet layout dropdown.

Step 9 — Write to Database

You have two options for writing data:

ButtonWhat it doesWhen to use it
Execute Upsert Updates existing records and inserts new ones. Existing records not in the file are left untouched. Regular price file updates — the safest option.
Replace All Deletes all existing records for this supplier, then inserts everything fresh from the file. When the supplier has sent a complete replacement catalogue.
Download CSV Saves the built output as a CSV file — no database write. When you just need an export file, not a database update.
⚠️ Replace All is irreversible. All existing records for the supplier will be deleted before the new data is inserted. Make sure you have reviewed the preview carefully before using this option.

A progress bar appears while the write is in progress. The status bar will confirm how many rows were inserted and updated when it finishes.

Shortening Rules

Shortening rules let you define automatic find-and-replace substitutions that run every time you build the output for a particular supplier. For example, you could replace "Capsules" with "Caps" to save characters.

Opening the rules editor

In the Supplier panel, click Edit Shortening Rules. A table appears with two columns: From (what to find) and To (what to replace it with).

How rules work

  • Matching is whole-word and case-insensitive — so "Tablet" will match "Tablet" and "TABLET" but not "Tablets" unless you specify it.
  • To match part of a word or use advanced patterns, start the From value with regex:.
  • Leave the To column empty to simply delete the matched text.

Click Save & Apply to Preview when done. Rules are saved and will be applied automatically on the next Build Output.

Specials File Module

Import promotional specials and catalogue deals sent by brands, and save them to the RxOne Specials database.

Typical Workflow

Select BrandChoose the brand from the dropdown on the right panel.
Import FileClick Import… and browse to the specials file (CSV or Excel).
Set Column MappingTell the app which columns in the file contain the barcode, description, and special price.
Review the GridCheck the imported rows — new, changed, and invalid items are highlighted in different colours.
Edit & CleanFix descriptions, barcodes, or prices directly in the grid. Use Bulk Find & Replace or Sort Invalid at Top to help manage problem rows.
Enter Special Name & DatesFill in the special name (e.g. April 2026 Catalogue), start date, and finish date.
Save to DatabaseClick Save to Database to write the specials.

Step 1 — Select a Brand

Click the Brand dropdown on the right panel and select the brand whose specials you are importing. The app loads the saved column-mapping settings for that brand automatically.

ℹ️ When the app loads, it automatically removes any specials from the database whose finish date was more than two months ago, keeping the database tidy.

Step 2 — Import a File

Click the blue Import… button at the bottom of the screen and browse to the specials file provided by the brand. The app accepts .csv and .xlsx / .xls files.

For known brands, the app will attempt to auto-detect the column mapping from the file's header row and fill in the grid automatically. For other brands, you may need to set the column mapping manually (see Step 3).

Step 3 — Column Mapping

In the Columns panel on the right, set which column number in the file maps to each field. Column numbers start at 1 (the leftmost column in the file).

FieldWhat it is
DescriptionProduct name / description
Special PriceThe special price. Can be a dollar amount (e.g. 12.99) or a percentage discount (e.g. 15%).
Barcode / PharmacodeThe product barcode or pharmacode used to match to stock
POS Note (optional)A message to display at the point of sale

You can also set the field delimiter (Comma, Tab, Semicolon, or Pipe) and whether to ignore the first line of the file (tick this if the first row is a header row).

Once set correctly, click Save Column Settings to remember these choices for this brand in future.

Step 4 — Review the Grid

After importing, the grid shows all the rows from the file. Each row is colour-coded to show its status:

Blue/Purple — New: this item does not exist in the current specials database
Pink/Red — Changed: this item exists but something has changed
Light Red — Invalid: this row has a problem and will be skipped on save
White — Unchanged: no changes from the current database

The Chars column shows the description length. Descriptions must be 40 characters or fewer.

💡 Click Sort Invalid at Top in the toolbar to bring all problem rows to the top of the grid, making them easy to find and fix.

Step 5 — Editing & Cleaning the Grid

Editing cells directly

You can double-click any editable cell in the grid to change its value. The editable columns are: Description, MultiBuy Qty, Special Price, POS Note, and Multi Retail.

Adding and removing rows

Use the buttons in the Row Actions panel on the right:

ButtonWhat it does
Add Blank LineAdds an empty row at the bottom of the grid for manual entry.
Delete Selected LineRemoves the selected row(s) from the grid (they will not be saved).
Clear POS NoteClears the POS Note field for all selected rows.
Bulk Find & ReplaceFind and replace text across all Description cells at once.

Looking up a barcode

If a row is missing a barcode, select that row in the grid and click Open Stockcards (get barcode/pharmacode)…. A search dialog will open where you can search by product name. When you select a result, the barcode is automatically filled in for that row.

Logging invalid items

Click the red Log Invalid Items… button in the toolbar to export a list of all invalid rows to a file. This is useful if you need to send a report back to the supplier about items that could not be matched.

Step 6 — Special Name & Dates

At the bottom of the screen, fill in:

FieldNotes
Special NameA descriptive name for this promotion, e.g. April 2026 Catalogue. If a special with the same name already exists for this brand, the existing record will be updated.
Start DateThe date the promotion begins. Click the calendar icon to pick a date.
Finish DateThe date the promotion ends. Defaults to one month from today.
Password (optional)If the brand requires a password to access the special at the POS, enter it here.

Step 7 — Save to Database

Click the green Save to Database button. The app will:

  • Create the special record (or update it if one with the same name already exists).
  • Delete any existing items for this special and replace them with the current grid contents.
  • Skip any rows marked as Invalid.

A progress indicator shows how many rows have been saved. A message will confirm the total when complete.

⚠️ Saving will replace all existing items for the named special. If you need to add to an existing special without removing old items, contact your system administrator.

Saving and loading the grid

Before saving to the database, you can save the current grid as a file for later using Save Grid… in the toolbar. You can reload it with Load Grid…. This is useful if you need to pause your work and come back later.

Common Questions

The file loaded but all the data is in one column

The file is likely a CSV that uses a different delimiter (such as a semicolon or tab). In the File Format panel, change the Field delimiter to match the file, then re-import.

All descriptions are too long

Click Bulk Truncate to cut everything to 40 characters, then manually correct any that no longer read clearly. Consider setting up Shortening Rules for that supplier so common long words are automatically abbreviated in future.

The barcode lookup can't find a product

Try searching by a shorter part of the product name, or check the spelling. If the product genuinely does not exist in the stock database, you will need to create it there first before it can be added to a special.

A row is showing as Invalid

An Invalid row in the Specials grid usually means the barcode could not be matched to a product in the database. Use the Stockcard lookup to find the correct barcode, or delete the row if the product should not be included.

I saved the wrong data — can I undo?

There is no undo button. If you wrote incorrect data, you will need to re-import the correct file and run Execute Upsert (or Replace All) again to overwrite it. For the Specials module, saving always replaces the existing items for that named special, so re-importing with the correct file will fix it.

The app is slow to respond after selecting a supplier

The app fetches the supplier's records from the database in the background. If the database is on a network drive and the network is slow, this may take a few moments. Wait for the status bar to show that the prefetch is complete before clicking Preview Changes.
