Specials Brand Mapping Guide

How to configure brand_import_mappings.json to automatically map a supplier's specials file into the Import Specials screen.

Overview

When you click Import… on the Specials tab, the app reads the supplier's spreadsheet and maps its columns into the standard specials grid (Barcode, Description, Special Price, MultiBuy Qty, etc.). For most one-off files this is done manually via the Columns panel on the right.

For brands that send specials in a consistent, named-column format (such as Green Cross Health), you can define a brand mapping in brand_import_mappings.json. Once configured, selecting the brand and clicking Import will automatically populate the grid — no manual column selection required.

The mapping also drives several derived fields that cannot come directly from a column:

  • Group ID (which rows belong to the same multi-product deal)
  • Get Lowest Free flag
  • Flybuys flag
  • Special Name and date pickers (auto-filled from the file's first row)

File location

brand_import_mappings.json sits in the same folder as PriceFileApp.exe: 

brand_import_mappings.json   ← same level as PriceFileApp.exe

The file is not bundled inside the .exe — it lives alongside it in the application folder and can be opened and edited with any text editor at any time.

✓
No rebuild needed — changes take effect next time the app loads the file.
⚠
JSON is strict about syntax. Use a code editor such as VS Code for editing; it will flag any missing commas, mismatched brackets, or stray characters before you save.

How it works

1 — Brand name lookup

When you select a brand in the Import Specials screen, the app looks up the brand's display name (as it appears in the Brand dropdown) in the JSON file. The key must match exactly, including capitalisation. 

// The brand name in the dropdown is "GXH"
"GXH": { // ← key must match exactly
  ...
}

If no match is found the app falls back to named-column auto-detection and the manual column-number combos — the same behaviour as for unmapped brands.

2 — Column resolution order

For each field the app resolves the source column in this priority order:

  1. 1
    Brand mapping The column name listed in "columns" for this brand in the JSON file.
  2. 2
    Known header names A built-in list of common column names (e.g. Barcodes, Product name, Promotion POS note) checked case-insensitively.
  3. 3
    Manual combo position The column number set in the Columns panel on the right of the screen.

Steps 2 and 3 are fallbacks used when no brand mapping exists. When a brand mapping is configured, step 1 applies for all mapped roles.

3 — Auto-fill on import

After the file is loaded, the app also reads the first data row to pre-populate the Special Name field and the Start / Finish date pickers. The columns used for this are taken from the special_name, start_date, and end_date roles in the brand mapping.

Columns reference

Each entry under "columns" maps a role name (used internally by the app) to the exact column header in the supplier's file (case-insensitive match).

Role Grid field populated Notes
barcode Barcode Barcodes or EAN codes. If the cell contains multiple barcodes separated by commas, all are stored joined by commas.
description Description Product name. If the description from the source file exceeds 40 characters, the app automatically looks up the product master description from the Details table (matched by barcode) and uses that instead. If no match is found, the description is truncated to 40 characters.
pos_note POS Note Text printed on the POS receipt or ticket at point of sale.
multibuy MultiBuy Qty The minimum quantity required to qualify for the deal (e.g. 2 for "buy 2 get 1 free").
multibuy_fallback MultiBuy Qty (fallback) Used only if multibuy is empty for a row. Useful when the file uses a separate "Quantity breaks" column for X-for-$Y deals.
deal_name Deal Name The name of the deal or promotion. Also used by the sequential_by_deal_name group_id rule to assign Group IDs.
product_price Special Price (dollar amount) A direct dollar price for the product (e.g. 4.99). Takes priority over discount-based price calculation. See the special_price rule.
discount_type Used to derive Special Price The type of discount. Currently only % is handled; if the value is %, the app formats the discount as a percentage string (e.g. 50%).
discount_value Used to derive Special Price The numeric discount amount, used together with discount_type when no product_price is present.
special_name Special Name field (auto-fill) Read from the first row only. Pre-fills the Special Name text box at the bottom of the screen (e.g. April 2026 Catalogue).
start_date Start Date picker (auto-fill) Read from the first row only. Must be in ISO date format (YYYY-MM-DD) or a similar parseable format.
end_date Finish Date picker (auto-fill) Read from the first row only. Same format requirements as start_date.
ℹ
All roles are optional. If a role is omitted, the app falls back to known header names and then to the manual combo position. You only need to include the roles where the supplier's column name differs from the built-in defaults.

Description fallback — product master lookup

The SpecialItems.Description field in RxOne is limited to 40 characters. Supplier specials files often contain longer product names (up to 60 characters in tested files).

When saving a special, if a product's description exceeds 40 characters, the app automatically queries the Details table in suppliers.mdb to find the product master description — matching on barcode / pharmacode. The master description is typically already within the 40-character limit and uses the standard RxOne abbreviation style.

The lookup follows this priority:

  1. 1
    Source description ≤ 40 chars Used as-is. No lookup is performed.
  2. 2
    Source description > 40 chars → Details lookup The app queries SELECT Description FROM Details WHERE PharmaCode = [barcode]. If a match is found and the result is non-empty, it is used as the description (still capped at 40 chars for safety).
  3. 3
    No Details match → truncate source If no product master record is found, the source description is truncated to 40 characters. This is a last resort and will only occur for products that do not yet exist in the RxOne database.
✓
In testing against the Vantage March 2026 special (103 products), all 26 products with descriptions longer than 40 characters resolved successfully from the Details table. No truncation fallback was required.
ℹ
The fallback only applies when saving to the database. The full source description is shown in the specials grid so you can review it before saving.

Rules reference

The "rules" block controls how derived fields are calculated. These fields cannot be read directly from a single column and require business logic.

group_id — Group ID assignment

Controls how rows are assigned to deal groups (the Group ID column in RxOne).

ValueBehaviour
sequential_by_deal_name Default Assigns a sequential integer Group ID to each unique Deal Name encountered in the file. The first unique deal name seen becomes Group ID 1, the second becomes 2, and so on. All rows sharing the same deal name receive the same Group ID. Rows with no deal name receive no Group ID.
from_column:<column name> Reads the Group ID value directly from the named column in the source file. Replace <column name> with the exact header. Example: from_column:Product A or B

flybuys — Flybuys loyalty flag

Sets the Flybuys column for every row to a fixed value.

ValueBehaviour
false Default All rows get Flybuys = N.
true All rows get Flybuys = Y (all items participate in Flybuys).
ℹ
There is no per-row Flybuys column option at this time. If different rows need different Flybuys values you will need to edit the grid manually after import.

lowest_free — Get Lowest Free flag

Controls the "Get Lowest Free" column, which tells RxOne to automatically give the cheapest qualifying item for free.

ValueBehaviour
disc_pct_and_multibuy_gt1 Default Set to Y only when both of the following are true:
  • The discount type is % and the discount value is greater than zero.
  • The MultiBuy Qty is greater than 1.
This covers the typical "buy 2, get the lowest priced item % off" scenario.
from_column:<column name> Reads the flag from the named column. Values of Y, YES, TRUE, or 1 (case-insensitive) map to Y; anything else maps to N.
always_false All rows get Get Lowest Free = N, regardless of other values.

special_price — Special Price calculation

Controls how the Special Price column is populated.

ValueBehaviour
product_price_then_disc_pct Default First checks the product_price column mapping. If a value is present, it is used as a dollar price (e.g. 4.99). If the product price column is empty for that row, the app looks at the discount_type and discount_value columns: if the type is %, the value is formatted as a percentage string (e.g. 50%). If neither is available, Special Price is left blank.
direct_column:<column name> Reads the Special Price directly from the named column with no further calculation. Use this when the file already contains the final formatted price string.

Adding a new brand

  1. 1
    Find the brand name In the Import Specials screen, select the brand from the dropdown. Note the name exactly as it appears — the JSON key is case-sensitive.
  2. 2
    Open a sample file from the supplier Check the column headers. Note the exact spelling of each column you want to map.
  3. 3
    Open brand_import_mappings.json in a text editor This file sits in the same folder as PriceFileApp.exe. Open it with any text editor — Notepad works, VS Code is preferred for syntax highlighting.
  4. 4
    Write the mapping block Copy the template below and fill in the column names and rules for the new brand.
  5. 5
    Save the file Save the JSON file. The next time the app starts, the new brand mapping will be available in the Import Specials screen — no rebuild required.

Minimal template

Start with this skeleton and add only the column roles and rules you need:

"BrandName": {
  "_description": "Friendly note about this brand — not used by the app",
  "columns": {
    "barcode":      "EAN",          // header in the supplier's file
    "description":  "Product Name",
    "pos_note":     "POS Text",
    "multibuy":     "Min Qty",
    "deal_name":    "Deal Name",
    "product_price": "Special Price",
    "special_name": "Promotion Name",
    "start_date":   "Start Date",
    "end_date":     "End Date"
  },
  "rules": {
    "group_id":      "sequential_by_deal_name",
    "flybuys":       false,
    "lowest_free":   "always_false",
    "special_price": "product_price_then_disc_pct"
  }
}
✓
You can omit any role you don't need. For example, if the file has no POS note column, simply leave out the pos_note line. The Columns panel in the app lets users still assign it manually if needed.

Example: discount-based price, no deal names

For a brand that uses a flat percentage discount and no multi-product deals:

"ACME": {
  "_description": "Acme Wholesale — monthly percentage specials",
  "columns": {
    "barcode":        "Barcode",
    "description":    "Item Description",
    "discount_type":  "Disc Type",
    "discount_value": "Disc %"
  },
  "rules": {
    "group_id":    "sequential_by_deal_name",
    "flybuys":     false,
    "lowest_free": "always_false",
    "special_price": "product_price_then_disc_pct"
  }
}

Example: Group ID read directly from file column

When the supplier's file already has a column that identifies which deal group each row belongs to:

"DIST": {
  "_description": "Distributor — group IDs pre-assigned in file",
  "columns": {
    "barcode":       "EAN13",
    "description":   "Description",
    "product_price": "Deal Price"
  },
  "rules": {
    "group_id":    "from_column:Group",  // reads the "Group" column directly
    "flybuys":     false,
    "lowest_free": "always_false",
    "special_price": "product_price_then_disc_pct"
  }
}

Full example: GXH (Green Cross Health)

The GXH brand uses an RxOne-generated Excel export as the specials source file. The file contains named columns, date information, and a mix of direct prices and percentage discounts. Here is the full mapping: 

"GXH": {
  "_description": "Green Cross Health — RxOne Excel export format",
  "columns": {
    "barcode":           "Barcodes",
    "description":       "Product name",
    "pos_note":          "Promotion POS note",
    "multibuy":          "Min qty",
    "multibuy_fallback": "Quantity breaks",
    "deal_name":         "Deal name",
    "product_price":     "Product price",
    "discount_type":     "Deal discount type",
    "discount_value":    "Deal discount value",
    "special_name":      "Promotion name",
    "start_date":        "Promotion start date",
    "end_date":          "Promotion end date"
  },
  "rules": {
    "group_id":      "sequential_by_deal_name",
    "flybuys":       false,
    "lowest_free":   "disc_pct_and_multibuy_gt1",
    "special_price": "product_price_then_disc_pct"
  }
}

How GXH import works step by step

  1. 1
    Special Name, Start & End dates Read from the first data row of the file's Promotion name, Promotion start date, and Promotion end date columns and pre-filled into the bottom bar fields.
  2. 2
    Barcode Read from Barcodes. Cells containing multiple barcodes (comma-separated) are stored joined with commas.
  3. 3
    Description Read from Product name. If the source description exceeds 40 characters, the app looks up the product master in the Details table by barcode and uses that description instead (truncating to 40 chars only as a last resort).
  4. 4
    Special Price If Product price has a value, that dollar amount is used. Otherwise, if Deal discount type is %, the value from Deal discount value is formatted as a percentage string (e.g. 50%).
  5. 5
    MultiBuy Qty Taken from Min qty. If empty, falls back to Quantity breaks.
  6. 6
    Get Lowest Free Set to Y only when the discount type is % and the MultiBuy Qty is greater than 1 (the disc_pct_and_multibuy_gt1 rule).
  7. 7
    Group ID Each unique Deal name value is assigned a sequential integer starting at 1. All products sharing the same deal name receive the same Group ID.
  8. 8
    Flybuys Always N for GXH (flybuys: false).

FAQ

The brand name appears in the dropdown but the mapping is not being applied. Why?
The JSON key must match the brand name exactly, including capitalisation and spaces. For example, "Green Cross Health" and "GREEN CROSS HEALTH" are treated as different keys. Check the brand name in the dropdown and compare it character-for-character with the JSON key.
My supplier's column header names change between files. Can the mapping handle this?
Not automatically. If the headers change you will need to either update the JSON mapping or use the manual Columns panel to select the correct column numbers for that file. If the supplier provides two variants you can list the preferred name in the mapping and rely on the fallback auto-detection for the alternative name (if it happens to match a known built-in header).
How do I map a field where the column name contains a colon (:)?
Colons in the column header value (the right-hand side of the mapping) are fine — they are just plain strings. The colon syntax (from_column:, direct_column:) only applies to the rules values on the left side of a rule, not to column names.
Can I use a list of column names to try in order?
This is noted as a supported syntax in the file's own _instructions comment, but the current app code resolves to a single string value per role. For now, use the single most reliable column name. If the column header varies, update the JSON when switching file formats.
Will the mapping survive a software update?
Yes — as of April 2026, brand_import_mappings.json is no longer bundled inside the .exe. It sits next to the exe in the application folder and is not touched by a software update. Edit it freely; your changes will persist across upgrades.
What happens to columns in the file that are not mapped?
They are ignored during the automatic mapping pass. The raw file data is still held in memory after import, so no data is lost — but only the mapped columns appear in the specials grid.
