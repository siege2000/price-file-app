What does the app do?

The Price File Builder takes price files from suppliers (CSV or Excel) and loads them into the RxOne database (suppliers.mdb). It handles the column matching, description tidying, and database update — all without any manual SQL.

The app remembers your settings for each supplier, so after the first time the work is much faster.

ℹ️ The app has two modes at the top: Price File (for regular supplier price updates) and Specials File (for specials promotions). This guide covers the Price File mode.

Step-by-step: processing a price file

  1. 1
    Select the supplier Pick the supplier from the dropdown at the top right. The app will silently start loading their existing database records in the background — by the time you get to the preview step, it will already be ready.
  2. 2
    Open the price file Click Open File and browse to the supplier's CSV or Excel file. If the Excel file has more than one sheet, a window will ask you which sheet to use — pick the one with the product data.
  3. 3
    Check the column mappings On the right panel, check that the columns are mapped correctly (PLU, Pharmacode, Retail, Cost, etc.). For suppliers the app already knows, these will be pre-filled. If anything looks wrong, change the dropdowns to the correct columns from the file.
  4. 4
    Check the TradeName settings Scroll down the right panel to the TradeName section. Check which columns are being used to build the product description and whether title case and unit normalisation are turned on. Again, these will usually be set correctly for known suppliers.
  5. 5
    Click Build Output Click the Build Output button. The app processes the file, applies description rules, removes rows with no identifying code, and shows the processed rows. The row count is displayed at the bottom of the screen.
  6. 6
    Preview Changes Click Preview Changes. The app compares your processed output against what is already in the database and shows you exactly what will change. NEW rows are records that don't exist yet. UPDATE rows will overwrite an existing record. Review the list and delete any rows you don't want to write by selecting them and pressing Delete.
  7. 7
    Fix any description warnings Rows where the description is over 40 characters are marked with ⚠. You must fix these before writing to the database. See the Fixing descriptions section below for how to do this quickly. Where a description is over 40 characters it will be treated as follows:
    • If it is a new product it must be fixed before it can be added to the suppliers price file
    • If it is an update to an existing product, the app will ignore the new description, and only update other details
  8. 8
    Save settings (first time only) If this is the first time you've processed this supplier, click Save Settings to store the column mappings. They will be restored automatically next time.
  9. 9
    Write to the database Click Execute Upsert to write the data. The app will insert new records and update existing ones. A confirmation message shows how many rows were inserted and updated. If you want to completely replace all records for the supplier (not just update), use Replace All instead.
✅ Prefer to export a CSV rather than write to the database? Use the Download CSV button after step 5 to save the processed file.

Fixing descriptions

The database has a 40-character limit on product descriptions (TradeName). The app highlights any that are too long with a ⚠ warning.

Option 1 — Bulk Truncate

Click Bulk Truncate to automatically cut all descriptions down to 40 characters. This is the quickest option when there are many long descriptions. Note that truncation cuts at exactly 40 characters, so check that the results still make sense.

Option 2 — Edit individually

In the preview grid, click on any description cell in the New_Description column and type your edited version. This is best when you only have a few rows to fix and want to be careful about what gets cut.

Option 3 — Add a shortening rule

If a particular word or phrase makes descriptions too long for a supplier consistently (e.g. "Tablets" → "Tab"), you can add a shortening rule. Click Edit Rules in the supplier panel. Rules support find/replace with optional whole-word and case-insensitive matching. Once saved, the rule will apply automatically every time you process this supplier's file.

⚠️ You cannot Execute Upsert while any description warnings remain. All ⚠ rows must be resolved first.

Saving settings for a supplier

After mapping the columns for a supplier the first time, click Save Settings. The app stores the mappings in supplier_settings.json and will restore them automatically the next time you open a file for that supplier.

Multiple sheet layouts

Some suppliers send an Excel workbook where different product categories are on separate sheets, each with a different column layout. You can save up to 6 separate layouts per supplier. After mapping the columns for a sheet, give it a name in the Sheet layout dropdown and click Save Settings. Next time, select the layout that matches the sheet you are working on.

ℹ️ Settings are saved to the data/ folder inside the app directory. If you ever need to reset a supplier back to defaults, you can delete their entry from supplier_settings.json using a text editor.

Specials files

At the top of the app, switch the mode to Specials File to process a supplier specials promotion file.

The Specials workflow has its own column mapping rules per brand, stored in brand_import_mappings.json. If a brand's specials file uses a different layout from what the app expects, contact your supervisor to update the mapping.

The Specials mode also includes a Stock Card lookup that searches the Healthsoft database by barcode — useful for confirming a product exists before adding a special.

Common questions

The column dropdowns are all wrong — the data is in different columns than expected.
This usually means the supplier's file has extra header rows at the top. Check the Skip rows setting (top of the app) and increase it by 1 or 2 until the data lines up correctly.
The app says "0 rows" after Build Output.
This usually means the Exclude rows with no Barcode, Supplier Code and Pharmacode filter has removed everything, because none of those columns were mapped. Check that at least one of Barcode, Supplier Code, or Pharmacode is mapped to a column in the file.
Preview Changes is showing everything as NEW, but these products already exist.
Check that the correct supplier is selected. If the supplier is correct, check that Supplier Code or Barcode is mapped — those are the fields used to match against existing records. If neither is present in the file, the app cannot find the existing records to update.
The app is not connecting to the database.
Check that the database path in Settings is correct and that you can access the network location. The Microsoft Access Database Engine must also be installed on your PC. Contact your IT support if the issue persists.
I accidentally wrote wrong data to the database.
Contact your supervisor immediately. Do not run the file again. The database may need to be restored from a backup.
The PLU column is showing numbers like "100234.0" instead of "100234".
This can happen with some Excel files. Make sure the PLU column is mapped correctly — the app automatically strips the ".0" from columns it recognises as ID fields. If it still occurs, check that the column header name matches one of the recognised names (PLU, Pharmacode, Barcode, SAP Code).

Tips & shortcuts

Keyboard shortcut in the preview grid

Select one or more rows in the Preview Changes grid and press Delete to remove them before writing to the database. This is useful for excluding products you don't want to update (e.g. discontinued items).

Check the CharCount column

After Build Output, the output table shows a CharCount column next to TradeName. Scan down this column — any value over 40 will need to be fixed before you can upsert.

Use Preview Changes even if you're confident

It only takes a moment and it lets you catch surprises — like a supplier changing their column order — before anything is written to the database.

Download CSV as a backup

Before running Execute Upsert on a large file, it's good practice to click Download CSV first. That way you have a copy of exactly what was loaded, which can help if anything needs to be checked later.

💡 If you're not sure whether to use Execute Upsert or Replace All — use Upsert. It is the safer option: it only adds and updates, it never removes existing records. Replace All deletes everything for the supplier first, so only use it when you're certain the incoming file is complete.
